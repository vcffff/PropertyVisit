# PropertyVisit — Design Brief

**Summary:** PropertyVisit — мобильное Flutter-приложение бронирования просмотров квартир: покупатель выбирает квартиру и свободный 30-минутный слот, менеджер подтверждает или отменяет запись. Один клиент с ролевой навигацией (buyer / admin).

**Date:** 2026-10-21
**Status:** confirmed (пользователь финализировал бриф явно, 2026-10-21)

## Продукт

- **Проблема:** просмотры согласовываются звонками; менеджер вручную назначает время, возможны дубли и забытые встречи.
- **Решение:** каталог квартир → выбор даты/времени из фиксированной сетки → бронирование → статусы (pending/confirmed/cancelled) → админ управляет записями.
- **Цель:** full-stack портфолио MVP. **Дедлайн: 23 октября 2026.**
- **Приоритет:** один сквозной поток — Login → Browse Properties → Select Date/Time → Book Viewing → See Booking Status → Admin Confirms.
- **Не делаем:** платежи, чат, карты, пуш-уведомления, доп. инфраструктуру.

## Роли и экраны

Один Flutter-клиент, навигация по роли:

| Buyer | Admin/Manager |
|---|---|
| Каталог квартир (цены, адреса, фото) | Управление квартирами |
| Детали квартиры | Список бронирований |
| Календарь свободных слотов | Подтвердить / отменить запись |
| Бронирование | — |
| Мои просмотры (статусы) | — |

Отдельной веб-админки для MVP нет.

## Бронирование (бизнес-правила)

- Фиксированное расписание: ежедневно 10:00–19:00 по локальной таймзоне объекта.
- Слоты по 30 минут; кастомных расписаний менеджера нет.
- Таймстемпы хранятся в UTC.
- Источник истины по доступности — Go-бэкенд.
- От двойного бронирования активного слота защищает partial unique index в PostgreSQL.
- Redis — только сессии и rate limiting; Redis-локи для бронирования **не** вводить.

## Визуальное направление

Премиальный минимализм в недвижимости: чистота подачи BI Group + ясность интерфейса Linear.

- Светлая тема
- Нейтральная палитра
- Крупная фотография объекта
- Чёткая типографика
- Просторные карточки
- Элегантный календарь бронирования
- Простые, профессиональные админ-экраны

## Технологии

- **Клиент:** Flutter, BLoC, Dio, go_router, flutter_secure_storage.
- **Бэкенд:** уже существует на Go (JWT + refresh token rotation, PostgreSQL, Redis, Kafka). **Не редизайнить.** Интегрироваться с его фактическим API-контрактом; временные mock-репозитории только там, где эндпоинты не готовы.

## Принципы реализации

- Практичная архитектура, без лишних абстракций.
- Не задавать продуктовых вопросов без блокирующей необходимости.

## Open questions

- Точный API-контракт бэкенда (эндпоинты, DTO) — сверить при интеграции; mock там, где не готово.
- Визуальная идентичность (логотип, точные цвета) — отсутствует; решается на этапе design DNA.
